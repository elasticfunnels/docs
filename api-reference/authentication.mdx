## Overview

The ElasticFunnels API uses **API keys** for authentication. Each key belongs to your user account and reaches only the projects (brands) you picked when you created it, as read-only or read and write. It can never do more than your own account can in those projects.

<Warning>
  Keep your API keys secure! Never share them publicly or commit them to version control. Treat them like passwords.
</Warning>

## Creating an API Key

1. In your project, go to **Settings → API**
2. Click **Create API key**
3. Name the key, pick its **Projects** and its **Access** (read and write, or read-only)
4. Click **Create API key** and confirm it's you with your passkey, authenticator code or a recovery code
5. Copy the key from the **Copy your new key** window. It is shown only once

<Note>
  Creating or regenerating a key needs [two-factor authentication](/account/two-factor-authentication) on your account and a confirmation in the last 10 minutes. Keys are created from a signed-in browser session only, and an API key can't create another key. Step-by-step help: [Connect the ef CLI and create API keys](/account/cli-and-api-keys#create-an-api-key).
</Note>

## Using Your API Key

Include your API key in the request header using the `EF-Access-Key` header:

```bash cURL
curl https://app.elasticfunnels.io/api/brands/{brand_id}/pages/all \
  -H "EF-Access-Key: your_api_key_here"
```

```javascript JavaScript
const headers = {
  'EF-Access-Key': 'your_api_key_here',
  'Content-Type': 'application/json'
};

const response = await fetch('https://app.elasticfunnels.io/api/brands/{brand_id}/pages/all', {
  headers: headers
});
```

```python Python
import requests

headers = {
    'EF-Access-Key': 'your_api_key_here',
    'Content-Type': 'application/json'
}

response = requests.get(
    'https://app.elasticfunnels.io/api/brands/{brand_id}/pages/all',
    headers=headers
)
```

```php PHP
<?php

$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, 'https://app.elasticfunnels.io/api/brands/' . $brandId . '/pages/all');
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_HTTPHEADER, [
    'EF-Access-Key: your_api_key_here',
    'Content-Type: application/json'
]);

$response = curl_exec($ch);
curl_close($ch);

$data = json_decode($response, true);
```

## Authentication Errors

If authentication fails, you'll receive one of the following responses:

### Invalid API Key

```json
{
  "message": "Invalid API key"
}
```
**Status Code:** `401 Unauthorized`

### No Brand Access

```json
{
  "message": "Invalid API key or brand access denied"
}
```
**Status Code:** `401 Unauthorized`

This error occurs when:
- Your API key is valid but doesn't have access to the specified brand/project
- You're trying to access a project you're not a member of

### Missing API Key

If you don't include the `EF-Access-Key` header, you'll be redirected to the login page (for browser requests) or receive a 404 error (for API requests).

## API Key Scope and Permissions

<Info>
  Your API key inherits all permissions from your user account for the specific project.
</Info>

API keys are:
- **User-specific**: Each key is tied to your user account
- **Project-scoped**: Each key reaches only the projects you picked (one, several, or all projects you can access)
- **Read-only or read and write**: chosen when you create the key
- **Permission-aware**: Within those projects, requests never go beyond your own role (Owner, Admin, Editor, etc.)

Scoped keys never reach organization settings, organization billing or team management. An older **Full access (legacy)** key can do everything your account can do in every project. You can swap it for a scoped key with **Convert to scoped key** on the API page.

### Example Permission Scenarios

**Owner/Admin**: Access to the project's content, analytics and settings endpoints

**Editor**: Access to content management endpoints (pages, products, funnels) but not billing or team management

**Viewer**: Read-only access to analytics and content

## Regenerating Your API Key

If your API key is compromised or you need to revoke access:

1. Go to **Settings → API**
2. Click **Revoke** on the key (it stops working at once), then create a new one. For a legacy full-access key, click **Regenerate** instead
3. Confirm it's you when asked
4. Update all integrations with the new key

<Warning>
  Regenerating an API key immediately invalidates the old key. Any integrations using the old key will stop working until updated.
</Warning>

## Testing Your Authentication

You can test your API key with a simple GET request to retrieve your brand details:

```bash
curl https://app.elasticfunnels.io/api/brands/{brand_id} \
  -H "EF-Access-Key: your_api_key_here"
```

A successful response will return your project information with a `200 OK` status.
