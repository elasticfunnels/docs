---
title: 'Upsell Forms (Gift Address and Custom Fields)'
description: 'Ask for a ship-to address or extra details on a one-click upsell, show the shipping and total, then charge the stored card once'
---

An upsell form collects a few details before a one-click upsell is charged. The most common use is a gift: the buyer adds a second pack and sends it to a friend, so the upsell needs the friend's address. The form can also collect your own fields (an engraving line, a gift note, a size).

The buyer's card is not asked for again. The form only collects the details, shows the price with shipping for that address, and charges the card from the first order when the buyer confirms.

## What the buyer sees

1. The buyer clicks the upsell button.
2. A form opens over the page: name, address, city, state, ZIP/postal code, country, and an optional phone.
3. The buyer clicks **Continue**. ElasticFunnels checks the address and works out shipping for that country from the product's shipping profile.
4. A summary shows the item, shipping, tax and the total, plus the ship-to address. The button reads **Confirm and pay $X**.
5. On confirm, the card on file is charged once and the funnel moves to the next step, the same as a normal one-click upsell.

If a field is missing or invalid, the form shows the error next to that field and nothing is charged. If the product does not ship to the chosen country, the country field says so and nothing is charged.

## Option 1: no code, add `form=` to the upsell tag

Add a `form` option to an upsell or downsell link tag:

```
[UPSELL=sleep-gummies-1 form=gift-address]
[DOWNSELL=sleep-gummies-1 form=address]
```

| `form=` | What it asks for | Marked as a gift |
|---------|------------------|------------------|
| `gift-address` | Recipient name and address | Yes |
| `address` | A different ship-to name and address | No |
| `fields` | Only your custom fields (see below) | No |

Any input on the page with a `data-ef-upsell-field` attribute is sent along as a custom field:

```html
<input data-ef-upsell-field="gift_note" placeholder="Add a note for the card">
[UPSELL=sleep-gummies-1 form=gift-address]
```

### Example: a gift block with a note and a decline link

Paste this on the upsell page. The button opens the gift form, the note rides along as the `gift_note` field, and the decline link moves the buyer to the next step without charging.

```html
<div class="gift-offer">
  <h2>Send a bag to someone you love</h2>
  <p>Same price, shipped to their door. We'll ask for their address next.</p>
  <label for="gift-note">Note for the card (optional)</label>
  <input id="gift-note" data-ef-upsell-field="gift_note" maxlength="200" placeholder="Happy birthday">
  <a class="btn" href="[UPSELL=sleep-gummies-1 form=gift-address]">Yes, send a gift bag</a>
</div>
<a href="[UPSELL_DECLINE]">No thanks, show me my order</a>
```

### Change the form's text, colors and fields

The built-in form takes a few more options on the same tag. `[UPSELL=]`, `[DOWNSELL=]` and `[QUICKBUY=]` all accept them:

```
[UPSELL=sleep-gummies-1 form=gift-address title='Send one to someone you love' intro='We ship it to their door with your message on the slip.' button='Send the gift for {total}' color='#c2185b' fields='phone,message']
```

Inside an `href="..."`, wrap each value in single quotes, as above. A value with no spaces needs no quotes.

| Option | What it changes | Default |
|--------|-----------------|---------|
| `title` | The heading of the form (up to 120 characters) | "Where should we send the gift?" for `gift-address`, "Where should we send it?" for `address`, in the visitor's language |
| `intro` | A short line under the heading, also shown on the summary (up to 400 characters) | None |
| `button` | The confirm button on the summary (up to 60 characters). `{total}` is replaced with the total, shipping and tax included | "Confirm and pay $X" |
| `color` | The button and focus color: a hex code (`#c2185b`), `rgb()`, `hsl()` or a color name | Green |
| `text-color` | The button's text color, same formats | White |
| `fields` | Which optional fields show, comma separated: `address2`, `phone`, `message`. `fields=none` shows only the required ones | `address2,phone` |

`message` adds a **Gift message** box (up to 300 characters). The message shows on the summary and is saved on the order as the `gift_message` flag.

Text from these options is shown as plain text, so HTML in it is displayed as typed and never runs. A color that is not a valid color is ignored and the default is used.

**Fields that are always there.** Recipient first and last name, address, city and country are always asked for, plus the ZIP or postal code (except in countries that have none, such as Hong Kong or the UAE) and the state for the US, Canada and Australia. `fields=` can't remove them: naming one of them, or a name that isn't a field, is ignored with a warning in the browser console and the form still opens.

**What is checked.** The form checks each field before **Continue**, and ElasticFunnels checks the same rules again on the server before any charge, so a page script that skips the form can't place an order with a missing or invalid field. A refused field gets its own error under it:

- every required field must be filled in;
- the phone, when given, may only hold digits, spaces and `+ ( ) - .`, with at least 6 digits;
- names and address lines up to 100 characters, the city up to 50, the gift message up to 300.

To restyle the form from your page's CSS instead, set these variables (a `color` option on the tag takes priority):

```css
:root {
  --ef-upsell-form-accent: #c2185b;      /* button and focus color */
  --ef-upsell-form-accent-text: #fff;    /* button text */
  --ef-upsell-form-bg: #fffaf5;          /* form background */
  --ef-upsell-form-text: #2b211b;        /* form text */
  --ef-upsell-form-radius: 18px;         /* corner radius */
}
```

## Option 2: your own form, call `ef.quickBuy`

If the page already has its own gift form, pass what it collected to `ef.quickBuy`. ElasticFunnels validates it, shows the summary with shipping, and charges on confirm.

```js
const result = await window.ef.quickBuy('sleep-gummies-1', {
  ship_to: {
    first_name: 'Ann', last_name: 'Lee',
    address: '1 Main St', address2: '',
    city: 'Toronto', state: 'ON', zip: 'M5V 2T6', country: 'CA',
    phone: '4165550100'
  },
  gift: true,
  fields: { gift_note: 'Happy birthday' }
});

// result = { success: true, nextUrl: '/next-step' }
//       or { success: false, code: 'cancelled' | 'invalid' | 'no_shipping_rate' | 'declined' | ..., error, errors }
```

`ef.quickBuy` does not leave the page on its own: send the buyer to `result.nextUrl` when you are ready. Pass `redirect: true` to have it go there for you.

The address keys also accept the names most page forms already use: `address1`, `region` or `province`, `postal_code` or `postcode`, `firstName`, `lastName`. `country` is the two-letter code (`US`, `CA`, `GB`). State is required for the US, Canada and Australia.

### Options

| Option | Meaning |
|--------|---------|
| `ship_to` | The recipient's address. Leave it out to ship to the buyer. |
| `gift` | `true` marks the order as a gift. |
| `fields` | Up to 20 custom fields. Keys are lower-case letters, digits and `_`; values up to 500 characters. |
| `confirm` | `false` skips the summary and charges straight away. The address is still checked first. |
| `redirect` | `true` goes to the next funnel step after a successful charge. |
| `form` | Opens the built-in form instead of passing `ship_to`: `{ name: 'gift-address', title, intro, button, color, text_color, fields }`. Takes the same options as the tag, for example `fields: 'phone,message'`. |
| `gift_message` | A gift message to save with the order (up to 300 characters). |

To get the price with shipping without charging (for example to show it in your own layout), call `ef.quickBuy.quote(code, { ship_to })`.

### Example: your own form, with the error shown and the redirect

```html
<form id="gift-form">
  <input name="first_name" placeholder="First name" required>
  <input name="last_name" placeholder="Last name" required>
  <input name="address" placeholder="Street address" required>
  <input name="city" placeholder="City" required>
  <input name="state" placeholder="State / province">
  <input name="zip" placeholder="ZIP / postal code" required>
  <select name="country"><option value="US">United States</option><option value="CA">Canada</option></select>
  <textarea name="gift_note" maxlength="200" placeholder="Note for the card"></textarea>
  <button type="submit">Send it as a gift</button>
  <p id="gift-error" role="alert"></p>
</form>
<script>
document.getElementById('gift-form').addEventListener('submit', async function (e) {
  e.preventDefault();
  var f = Object.fromEntries(new FormData(e.target));
  var note = f.gift_note; delete f.gift_note;
  var result = await window.ef.quickBuy('sleep-gummies-1', {
    ship_to: f,
    gift: true,
    fields: { gift_note: note }
  });
  if (result.success) {
    window.location.href = result.nextUrl;
  } else if (result.code !== 'cancelled') {
    document.getElementById('gift-error').textContent = result.error;
  }
});
</script>
```

`cancelled` means the buyer closed the summary; nothing was charged and there is nothing to show.

## Show the gift offer only when it can ship

A gift or ship-to upsell needs a main sale that can pay for a parcel to another address. ElasticFunnels already hides a `[UPSELL=CODE form=gift-address]` or `form=address` link (the whole link element) when it can't, and refuses the charge if a page asks anyway. To swap in a different offer for those buyers, wrap the gift block in a template check:

```html
@if(upsell_form.can_ship_to)
  <h2>Send a bag to someone you love</h2>
  <input data-ef-upsell-field="gift_note" maxlength="200" placeholder="Note for the card">
  <a class="btn" href="[UPSELL=sleep-gummies-1 form=gift-address]">Yes, send a gift bag</a>
@else
  <h2>Add a second bag to your order</h2>
  <a class="btn" href="[UPSELL=sleep-gummies-1]">Yes, add it</a>
@endif
<a href="[UPSELL_DECLINE]">No thanks</a>
```

`upsell_form.can_ship_to` is decided on the server, so the buyer never sees an offer that would fail. In a [backend script](/backend-scripts/data-functions), the same answer is `canUpsellShipTo()`.

If your own form is built in JavaScript, ask the browser instead. `ef.quickBuy.canShipTo()` resolves to `true` or `false`:

```html
<div id="gift-offer" hidden>
  <h2>Send a bag to someone you love</h2>
  <!-- your gift form from Option 2 -->
</div>
<div id="plain-offer" hidden>
  <a class="btn" href="[UPSELL=sleep-gummies-1]">Add a second bag to your order</a>
</div>
<script>
window.ef.quickBuy.canShipTo().then(function (ok) {
  document.getElementById(ok ? 'gift-offer' : 'plain-offer').hidden = false;
});
</script>
```

### Example: a page whose gift form calls `handleLovedOneGift`

Some landing pages ship with their own "send one to a loved one" form that calls a function named `handleLovedOneGift` with the package the buyer picked and the address they typed. Map each package to its product code and hand the rest to `ef.quickBuy`:

```html
<script>
window.handleLovedOneGift = function (o) {
  var codes = { PKG1: 'sleep-gummies-1', PKG3: 'sleep-gummies-3' };
  return window.ef.quickBuy(codes[o.packageKey], { ship_to: o.shippingAddress, gift: true });
};
</script>
```

## Shipping and tax

- Shipping is charged from the product's [shipping profile](/products/product-management) for the ship-to country (and state, where the profile has state rates), not the buyer's address.
- A product whose profile has no rate for that country cannot be sent there: the form says so before anything is charged.
- A product with no shipping profile, or a profile with no rates, ships free.
- Tax is worked out for the ship-to address the same way as on checkout.

## What is saved on the order

- The upsell order's **shipping** name and address are the recipient's. The **customer** and billing details stay the buyer's, so receipts and tracking emails go to the buyer.
- The recipient's phone, the gift mark and your custom fields are saved as order flags.
- Fulfillment providers get the recipient's name, address and phone on the label.

Open the order in **Reports** → **Conversions** to see them: its drawer has an **Upsell form** section with the ship-to, the gift mark, each custom field and a **Main order** link to the order the buyer placed first.

## Gift lines on the thank-you page

On the thank-you page, read the order with [`getSessionOrders()`](/forms/thank-you-pages): it holds the main product and every upsell from this checkout. Each product line (also in [`getOrders()`](/backend-scripts/data-functions#getorderssortby-limit)) says whether it is a gift and where it ships:

| Field | Meaning |
|-------|---------|
| `is_gift` | `true` for a line bought with `form=gift-address` or `gift: true` |
| `ship_to` | `{ name, address, city, state, zip, country }` when the line ships somewhere other than the order's address, otherwise `null` |
| `gift_fields` | Your custom fields for that line, for example `{ gift_note: 'Happy birthday' }` |

```html
@set(orders = getSessionOrders('newest', 10))
@if(orders.length gt 0)
<ul>
  @foreach(o in orders)
  @foreach(item in o.products)
  <li>{{ item.name }} &times; {{ item.quantity }}, {{ item.price | currency }}
    @if(item.is_gift)
    @if(item.ship_to)
    <br>Gift, ships to {{ item.ship_to.name }}, {{ item.ship_to.city }}, {{ item.ship_to.country }}
    @else
    <br>Gift
    @endif
    @if(item.gift_fields.gift_note)
    <br>Note: {{ item.gift_fields.gift_note }}
    @endif
    @elseif(item.ship_to)
    <br>Ships to {{ item.ship_to.name }}, {{ item.ship_to.city }}, {{ item.ship_to.country }}
    @endif
  </li>
  @endforeach
  @endforeach
</ul>
@endif
```

The gift lines show on the first load of the thank-you page, right after the charge. `country` is the two-letter code (`CA`, `GB`).

## Limits

- Works with NMI, Stripe and the Test merchant (the gateways that charge a stored card for one-click upsells). With other merchants the form shows an error and nothing is charged.
- Card buyers on NMI and Stripe can send gifts. Apple Pay buyers on NMI can too: the first sale saves the card, and upsells charge that saved card.
- If the bank declines that saved Apple Pay card, a plain upsell falls back to the Apple Pay sheet. The sheet can't carry the recipient's address yet, so a gift or ship-to form says the payment was declined and charges nothing. This is rare.
- PayPal buyers can't send a gift: `upsell_form.can_ship_to` is `false` for them and the gift link is hidden. Wrap the offer in `@if(upsell_form.can_ship_to)` (above) to show them something else.
- Needs an active purchase session, like every one-click upsell. If the session has ended the form says so.
- If the buyer already bought that upsell in this session, the form says so and does not charge again. Clicking **Confirm** twice also charges once.
- The form needs JavaScript. Without it, a link with `form=gift-address` or `form=address` shows a short "not available" message and charges nothing, so an order never ships to the wrong address. A `form=fields` link works as a plain upsell without the fields.
