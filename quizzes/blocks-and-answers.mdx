This page covers how the blocks on a quiz screen behave for the visitor: loader timing, height and weight answers, answer variables, validation, pricing plans, the Back button, colours, and what visitors do not see. To build and publish a quiz, see [Build and publish a quiz](/quizzes/build-and-publish).

## Loader timing
{/* SCREENSHOT: Loading block settings · Duration (sec), Start after (sec) · desktop */}

The **Loading** block takes its timing in **seconds**:

| Setting | Range |
|---------|-------|
| **Duration (sec)** | 1 to 60 seconds. A blank or 0 value runs for 1 second. |
| **Start after (sec)** | 0 to 60 seconds. |

A value of 1000 or more is read as milliseconds and converted (3000 runs for 3 seconds), so loaders set up in milliseconds keep working.

## Height and weight answers
{/* SCREENSHOT: Height and Weight blocks · unit switch · mobile */}

The visitor can answer the **Height** block in feet and inches or in centimetres, and the **Weight** block in pounds or kilograms. Whatever unit they pick, the answer is stored as one number in metric units, rounded to one decimal:

- height in **cm**;
- weight in **kg**.

So a visitor who enters 5'10" is stored as 177.8, and 180 lb as 81.6.

The unit details are available as variables, where `<id>` is the block's ID:

| Variable | Value |
|----------|-------|
| `<id>_unit` | The unit the visitor picked: `ft` or `cm` for height, `lb` or `kg` for weight |
| `<id>_cm`, `<id>_in` | Height in centimetres and in total inches |
| `<id>_ft`, `<id>_in_rem` | Height as feet plus remaining inches (when entered in feet and inches) |
| `<id>_kg`, `<id>_lb` | Weight in kilograms and in pounds |

The first Height block and the first Weight block with an answer can also be read as `height` and `weight`. Those are the names the default BMI formula uses, so this computed variable works whatever unit the visitor chose:

```text
weight / ((height/100) ** 2)
```

## Print an answer with a variable

Put a block's ID in double square brackets to print the visitor's answer in any text, heading or option label:

```text
Your goal: [[goal]]
```

`[[goal]]` prints the plain answer (for example `lose`). `[[goal.value]]`, `[[goal.answer]]` and `[[ responses.goal ]]` keep working too. A visibility rule on the bare block ID compares that same plain answer.

## Validation
{/* SCREENSHOT: Quiz screen · validation message under a field · mobile */}

The visitor cannot go on until the screen's answers pass these checks. The message shows under the block, in the page's language (English, Romanian or Portuguese).

| Block | Setting | Check |
|-------|---------|-------|
| **Phone** (or a **Field** with type Phone) | | A phone number with 7 to 15 digits. Text such as `abc` is refused. |
| **Field** with type Number | **Min (number)**, **Max (number)** | The number is within the range. |
| **Age** | **Min age**, **Max age** | The age is within the range. |
| **Multiple Choice** (or a choice block with **Allow multiple choice**) | **Minimum selections**, **Maximum selections** | The visitor picked at least the minimum and at most the maximum. 0 or blank means no limit. |

Fields marked required must be filled in, and an email field needs a valid address.

## Videos, links and HTML

**Videos.** A video block, or an intro video on a question, plays inside the quiz only when its address comes from a known video player: YouTube, Vimeo, Wistia, Loom, Vidalytics, VTurb (ConverteAI), Bunny Stream (`iframe.mediadelivery.net`), JW Player, Vidyard, Dailymotion, TrackPlay, Cloudflare Stream, Streamable, Facebook video and TikTok. Use the player's embed or share link over `https`. Any other address, including a file URL on a Bunny pull zone (`*.b-cdn.net`), is not embedded; use the Bunny Stream player link instead.

**Links and redirects.** Buttons, outcome redirects and other link fields accept `http://` and `https://` addresses, `mailto:`, `tel:` and paths on your own domain (`/thank-you`). Publish refuses any other kind of address. See [Publish checks](/quizzes/build-and-publish#publish-checks).

**Answers shown back.** When a variable such as `[[goal]]` or `{{ name }}` prints what a visitor typed, it shows as plain text. HTML a visitor types is shown as text, never run.

**Your own HTML.** Text and HTML blocks keep their formatting (bold, links, lists, colours, fonts, alignment). Scripts, `on...` event attributes and styles that pin an element over the page (`position`, `z-index`, `top`, `left` and similar) are removed when the quiz shows.

## Pricing plans
{/* SCREENSHOT: Price block with the Plans layout · plan settings open · desktop */}

A **Price** block set to show plans lists each plan as a card with a radio button. Visitors can tap a card, or press Tab to reach the plans and pick one with the arrow keys or Space. Screen readers announce which plan is selected.

Each plan has these settings in the builder:

| Setting | What it does |
|---------|--------------|
| **Plan name** | The name on the card, for example `4-week plan`. |
| **Price**, **Old price** | The price, and the crossed-out price shown next to it. |
| **Plan length (days)** | How many days the plan covers. The per-day price is worked out from it. |
| **Per day** | Your own per-day text. It is used only when the plan has no length. |
| **Checkout product code** | The product code of the plan in your checkout. |

**Per-day price.** When a plan has a length, the card shows the price divided by the number of days, for example `$19.99` over 30 days shows `$0.67 / day`. If you leave **Plan length (days)** empty, the length is read from the plan name when it says one (`7-day`, `4-week`, `3-month`, `monthly`, `yearly`). With no length at all, the card shows your **Per day** text, unless that text is higher than the plan's price.

**Plan to checkout.** When the visitor leaves the pricing screen through a link to your checkout, the chosen plan goes with it as `?p=<checkout product code>`, so the checkout opens on that product. If the visitor does not pick a plan, the plan marked **Selected** goes, or the first plan when none is marked. A plan with no product code leaves the link as it is.

In the templates, the plans card is centred on the pricing screen, and the screen's own button takes the visitor on.

## Back button and page navigation

The setting on the screen wins. A screen with **Allow to go back** turned on shows a Back button, even when **Show page navigation**, the quiz-wide switch in the layout settings, is off.

**Show page navigation** only sets the default for screens where **Allow to go back** was never changed: with the switch on, those screens show Back, except the first screen, where there is nothing to go back to. With the switch off, they show none. The builder preview follows the same rule.

When there is no Back button, the progress bar fills the header. A logo set to the right stays at the right edge, and a logo image that fails to load is left out of the header.

## Colours and readable text
{/* SCREENSHOT: Quiz screen · selected option on a dark primary colour · mobile */}

The templates and the builder's default and preset themes use darker shades of their primary, success and warning colours, so text on them meets the WCAG AA contrast level. For example the weight-loss green is now `#15803d` (was `#22c55e`) and the default red is `#ce4145` (was `#e5484d`).

Quizzes saved with the old builder defaults (`#e5484d`, `#16a34a`, `#f59e0b`) show the darker shades automatically. Colours you picked yourself are kept as you set them.

Text on a coloured fill is picked to stay readable on that colour: white on dark fills, dark text on light fills. This applies to buttons, selected options in single and multiple choice, badges and the unit switch on height and weight. On range charts, the segment labels use a darker shade of the bar colour so they can be read, and the bars keep their colour.

## Keyboard and screen readers

- Single choice, multiple choice and rating questions work as radio and checkbox groups. Press Tab to reach the group, use the arrow keys to move, and Space or Enter to pick. A focus ring shows where you are.
- On each new screen, focus moves to its heading and screen readers hear "Step 2 of 8" (with the real numbers). The progress bar is announced too, and the Back button is read as "Go back".
- Lead fields are a real form with labels, so browsers can fill in name, email and phone, and Enter submits the screen. When a field has an error, the error is announced and focus moves to the first field to fix.
- Age, height and weight show their error message under the picker when Continue fails (for example "Age must be at least 16.").

## What visitors do not see

- **AI Generated Text block:** personalized AI text is not generated on live pages yet, so the block is hidden from visitors. In a preview it shows a note in its place, never the prompt.
- **Blocks with template example values:** hidden on the live quiz until you edit them. See [Template example values](/quizzes/build-and-publish#template-example-values).

## If the quiz is missing or empty

A page set to show a quiz keeps its own HTML when the quiz cannot be shown: the quiz was deleted, it has no blocks, or it fails to load. Put fallback content in the page (for example a link to your offer) so visitors never land on a blank page.
