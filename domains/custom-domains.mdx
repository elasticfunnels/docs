Using a custom domain provides a branded URL and increases user trust through SSL encryption.

## Setup Instructions
{/* SCREENSHOT: Setup Instructions · domain settings or DNS setup screen · desktop */}

### Step 1: Add Domain
1. Go to the "Domains" section in your dashboard
2. Click "Add Domain" and switch to "Custom Domain"
3. Enter your domain (e.g., example.com)

### Step 2: SSL Configuration
1. If you need SSL now, check "I want SSL for this domain"
2. If not, request SSL later from the domains list by clicking the options button and selecting "Request SSL" once the domain is validated

### Step 3: Merchant Association
1. Associate the domain with a merchant to automatically update buy links (e.g., Buygoods, Clickbank, Digistore24)
2. Optionally, add reCAPTCHA site and private key for collection forms

### Step 4: DNS Setup
1. Update your DNS with the required A record and TXT record for validation. Both must be added
2. You'll receive an email once validated. If you encounter issues, email support

## What a domain is used for

Each domain has one or more uses. Open **Domains**, click the edit icon on the domain's row, and go to the **Uses** tab:

- **Funnel pages**: visitors open your funnel pages and checkouts on this domain.
- **Tracking**: your tracking script and pixel load from this domain, so browsers treat them as first party.

Keep at least one use checked.

## DNS Configuration
{/* SCREENSHOT: DNS Configuration · domain settings or DNS setup screen · desktop */}

### Required Records
- **A Record**: Points your domain to our servers
- **TXT Record**: Validates domain ownership

### Common DNS Providers
- **Cloudflare**: DNS management with additional CDN benefits
- **GoDaddy**: Simple DNS interface for basic setup
- **Namecheap**: User-friendly DNS management
- **Google Domains**: Clean interface with Google integration

### Using Cloudflare
If your domain's DNS is on Cloudflare and the records are proxied (orange cloud), open **SSL/TLS > Overview** in Cloudflare and set the encryption mode to **Full**. Do not use **Full (strict)** or **Automatic**: with those, Cloudflare refuses the certificate on our servers and visitors see Cloudflare **error 526** instead of your pages. Traffic between Cloudflare and ElasticFunnels stays encrypted in Full mode.

If you switch the records to DNS only (grey cloud), no Cloudflare SSL setting applies and we issue the certificate for the domain ourselves.

## Moving a Domain to Another Project
You can hand a domain to another project in the same organization without setting it up again. DNS records, SSL and the validated status carry over, so there is nothing to re-verify.

1. Go to **Domains**, open the options menu on the domain's row and choose **Move to another project**
2. Pick the target project. Only projects in your organization are listed, and you need permission to manage domains in both projects
3. Read the preview. It lists what in the current project stops using the domain: funnel links, blogs, courses, the courses domain setting and tracking scripts. If the domain's merchant belongs to the current project, the domain is moved without a merchant; assign one in the new project afterwards
4. Choose what happens to the pages on the domain. By default they stay in the current project without a domain. You can move them along with the domain instead, which runs in the background
5. Confirm. A domain moved without its pages switches over right away

Projects that are not part of an organization can move domains between each other only when they have the same owner.

From the command line: `ef domains move shop.example.com --to-brand "Main Store"` shows the same preview and asks before moving. Add `--with-pages` to move the pages too, or `--dry-run` to only see the preview.

## Troubleshooting Common Issues
{/* SCREENSHOT: Troubleshooting Common Issues · domain settings or DNS setup screen · desktop */}

### Domain Not Validating
- Double-check DNS records are correctly entered
- Allow 24-48 hours for DNS propagation
- Verify you have access to modify DNS settings
- Contact your DNS provider if records aren't updating

### SSL Certificate Problems
- Ensure domain is fully validated before requesting SSL
- Check for mixed content issues (HTTP resources on HTTPS pages)
- Clear browser cache and cookies
- Verify all subdomains are covered by the certificate

### Cloudflare Error 526 (Invalid SSL Certificate)
Your domain is on Cloudflare with SSL/TLS set to **Full (strict)**. Change it to **Full** under **SSL/TLS > Overview** and save; the pages come back right away. We check every live domain hourly and email you if this happens.

### Buy Link Issues
- Confirm merchant association is properly configured
- Test buy links after domain setup
- Verify affiliate tracking still works with custom domain
- Check payment processor domain whitelist settings

## Best Practices
{/* SCREENSHOT: Best Practices · domain settings or DNS setup screen · desktop */}

### Domain Selection
- Choose brandable, memorable domain names
- Avoid hyphens and numbers if possible
- Consider multiple domain extensions (.com, .net, etc.)
- Check trademark conflicts before purchasing

### Security Maintenance
- Enable automatic SSL renewal
- Regularly monitor certificate expiration dates
- Keep DNS records updated and documented
- Use strong authentication for domain registrar accounts

### Performance Optimization
- Use CDN services for global performance
- Enable GZIP compression at domain level
- Implement proper caching headers
- Monitor site speed and uptime regularly
